# القرآن الكريم — Quran App

A production-grade Quran reading app built on **one Expo/React Native codebase**
that ships three ways: a native **Android APK**, an installable **web PWA**, and
an iOS build (via Expo).

The mushaf is rendered the way the printed Madani Mushaf is: the actual
**QCF Madani 1405 page layout** with **604 per-page page fonts**, so every screen
is a real Mushaf page — not reflowed text. Reading, page navigation and Quran
text search work **fully offline**; recitations and additional translations are
fetched on demand from public, key-less APIs and are never bundled.

---

## Features

- **Phone-sized Mushaf pages** — per-word QCF Madani 1405 layout (604 pages) with
  per-page fonts, ported from the *Wird PWA v2* fit technique. Tap any word to
  select its ayah.
- **Three navigation modes** — سورة (surah) · صفحة (page) · جزء (juz), all derived
  from the bundled data.
- **Offline Quran search** — normalised Uthmani text search, plus optional search
  inside the bundled tafsir. No network used.
- **22 reciters** — per-ayah and per-surah recitations streamed from the AlQuran
  Cloud CDN, with a queue, repeat modes, playback-rate control and a mini-player.
- **Exactly one bundled tafsir** — التفسير الميسّر (`ar.muyassar`), available fully
  offline. Other editions are fetched online from the Quran.com API.
- **On-demand translations** — fetched per surah, never bundled.
- **Bookmarks & last-read progress** — stored locally.
- **Warm editorial palette** — cream/brown design system; the sky-blue accent
  (`#6BA3D6`) is reserved **exclusively** for the «لحظة رناد» feature.
- **PWA** — web manifest, service worker (app-shell precache + runtime caching)
  and SPA fallback, so the web build installs and works offline.
- **Background audio on Android** — lock-screen controls via `expo-audio`.

## Getting started

Requirements: **Node ≥ 22.13** and npm (the project uses `package-lock.json`).

```bash
npm ci                      # install exact dependencies
cp .env.example .env        # optional; see "Configuration" below
npm start                   # start the Expo dev server
```

Then:

```bash
npm run android             # open on an Android device/emulator
npm run ios                 # open on iOS (macOS)
npm run web                 # open the web app
```

> Adding a library with native code requires a **development build**
> (`npx expo run:android` / `npx expo run:ios`) — Expo Go cannot load it.
> Prefer `npx expo install <pkg>` so versions stay SDK-compatible.

### Quality gates

```bash
npm run typecheck           # tsc --noEmit
npm run lint                # expo lint
```

Both must pass before a change is considered done.

## Building the web PWA

```bash
npm run export:web          # expo export --platform web  ->  dist/
```

`dist/` is a static single-page app. The PWA shell lives in [`public/`](./public):

- `public/index.html` — RTL document `<head>` (manifest link, `theme-color`,
  Apple meta, service-worker registration).
- `public/manifest.json` — name, icons, `display: standalone`, theme colors.
- `public/sw.js` — precaches the app shell, network-first for navigations,
  cache-first for same-origin assets (skips cross-origin audio/APIs).
- `public/_redirects` — SPA fallback (`/* /index.html 200`).
- `public/icons/*.png` — 192/512/512-maskable/apple-touch icons, generated by
  `node scripts/generate-pwa-icons.mjs` (dependency-free).

Serve `dist/` over **HTTPS** to test installability:

```bash
npx serve dist
```

Deploy `dist/` to any static host (Netlify, Vercel, GitHub Pages, Cloudflare
Pages, …). `_redirects` covers Netlify/Cloudflare; add an equivalent rewrite for
other hosts.

## Android APK

### GitHub Actions (no account or secrets needed)

[`.github/workflows/apk.yml`](./.github/workflows/apk.yml) builds a real,
installable release APK on every push to `main`/`master`, on PRs, and on manual
dispatch. It runs typecheck + lint, generates the native project with
`expo prebuild`, and builds with Gradle. Download the artifact
**`quran-app-release-apk`** from the workflow run and sideload it.

The release variant is signed with the debug keystore generated by `prebuild`, so
it installs on any device but is **not** suitable for store submission.

### EAS Build (signed, store-ready)

[`eas.json`](./eas.json) defines three profiles:

| Profile | Output | Use |
| --- | --- | --- |
| `development` | APK dev client | Local native development |
| `preview` | **APK** | Internal testing / sideload |
| `production` | **AAB** (auto-incremented) | Play Store submission |

```bash
bunx eas-cli build --profile preview --platform android     # APK
bunx eas-cli build --profile production --platform android  # AAB
bunx eas-cli submit --platform android
```

Or `npx eas-cli@latest …` on non-Bun setups.

## Configuration

No secret is required. The app talks to public, key-less APIs, configurable via
optional `EXPO_PUBLIC_*` overrides in `.env` (see [`.env.example`](./.env.example)):

- **AlQuran Cloud** — `https://api.alquran.cloud/v1` (recitation audio, text).
- **Quran.com API v4** — `https://api.quran.com/api/v4` (reciter catalog, tafsir editions).
- **EveryAyah** — `https://everyayah.com/data` (fallback per-ayah audio).

`EXPO_PUBLIC_*` values are inlined into the client bundle at build time and are
**not** secret — never put credentials there.

## Data & provenance

The app bundles a small, fixed set of Quranic data and fonts so reading, search
and the Mushaf layout work offline. Full sourcing, licenses and reproduction
steps are documented in **[`docs/PROVENANCE.md`](./docs/PROVENANCE.md)**.

| Bundled asset | Source |
| --- | --- |
| `assets/data/quran.json` | AlQuran Cloud — `quran-uthmani` (Uthmani text, 6236 ayat) |
| `assets/data/tafsir.json` | AlQuran Cloud — `ar.muyassar` (التفسير الميسّر, KFGQPC) |
| `assets/data/mushaf-layout.json` | Madani 1405 / QCF layout — `SakinaDevGroup/al_quran_madani` v1.0 |
| `assets/mushaf/fonts/*.woff2` | 604 QCF per-page page fonts + ornaments (KFGQPC, via QUL) |
| `assets/fonts/AmiriQuran.ttf` | Amiri Quran — SIL OFL 1.1 (`assets/fonts/OFL.txt`) |

**Not bundled:** recitations, translations and non-Muyassar tafsir — all fetched
at runtime. No audio ships inside the app and no API keys are bundled.

scripts/                  generate-font-map.mjs · generate-pwa-icons.mjs
